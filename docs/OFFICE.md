# 像素办公室（/office）· 第三版

一个可选的动效前端：把调度台画成一间像素风办公室，每个智能体是一个会走动的小人。它只是现有 API 和 WebSocket 事件的另一种视图，不改后端数据模型。现有的看板前端保留，`UI.md` 的 Apple 风格只管 `/desk` 等页面；`/office` 的视觉规范以本文为准。

**演变。** 第一版是一张生成的斜俯视办公室插画，质感好，但遮挡靠手调长方形、坐的位置靠目测，连续几版出现人嵌进柜台、腿躺在桌上。第二版改成正面俯视的格子拼图，遮挡对了，画面却变得平淡，用户明确不接受。第三版：**画面回到第一版那张插画，遮挡换成像素游戏的正规做法**——把会挡住人的物体按真实轮廓从画里抠成遮挡件，人和遮挡件统一按触地线排序。第二版里和美术无关的部分（排序规则、栅格寻路、导演、空闲行为、昼夜、检查页、演示脚本）保留；格子地面、家具图集、调色板、正面坐姿删除。

参考气质：第一版插画本身——暖色、斜俯视、阳光从左侧窗户照进来，Q 版两头身角色，左右两侧是像素描边的值班名单面板。

## 1. 部署形态

- 独立应用 `apps/office`（Vite + React 19 + PixiJS 8），构建产物由 API 在 `/office/` 托管，配置 `IDESK_OFFICE_DIST` 指向 dist；没配就不托管，主前端也不显示入口。
- 主前端侧栏在 `/office/` 可达时显示「像素办公室」入口（`GET /api/meta` 返回 `{ office, build }`）。
- Dockerfile 构建参数 `WITH_OFFICE`（默认 `true`）决定是否构建并打包 office。
- office 自己不做登录页：未登录（401）时跳回主前端 `/login?from=/office/`。
- 部署后打开着的页面在 WS 重连时比对 `build`，变了就自动刷新；素材 URL 带构建戳。

## 2. 画面与图层

**背景。** 第一版的办公室插画 `assets/raw/background.png`（1672×941），运行时用 `public/background.webp`。世界坐标就是背景的像素坐标。舞台按窗口等比缩放（背景不是严格的像素网格，不要求整数倍），最近邻采样。

**图层**（从下到上）：

1. 背景：整张插画。墙、窗、白板、门、地板、所有家具都在里面。
2. 物体层：遮挡件（§3）、人、桌上的任务卡，全部按 `sortY` 排序，这是唯一需要排序的层。
3. 效果层：气泡、飞行中的卡片和信封、纸屑。永远在物体之上。
4. 光照：昼夜色块和工位暖光（§8）。

## 3. 遮挡件

**是什么。** 背景里会挡住人的物体——工位桌（连显示器）、前排椅子的椅背、前台柜台、会议桌和会议椅、沙发的扶手和前沿、绿植、书架、玻璃隔断等——按它的真实外轮廓（含描边）从背景里抠出来的一块图。遮挡件画在背景上完全相同的位置，像素和背景重合，所以没人站在它后面时看不出它存在；有人在它后面时，它就按轮廓盖住人。

**数据。** `layout.json` 的 `occluders`：每件 `{ id, polygon, baseline }`。`polygon` 是背景像素坐标的顶点列表，沿物体描边的外沿走，误差不超过 1 像素；`baseline` 是物体落地前沿的 y（桌腿、柜台底、椅轮落在地板上的那条线）。baseline 可以低于多边形的下沿：前排椅子只抠到椅背和扶手，但它的落地前沿是更低的椅轮。座位脚底取落地点的中心、遮挡件 baseline 取落地的前沿，所以坐在前排椅子上的人天然排在自己的椅背后面，不需要任何偏移。人坐在旁边、腿伸进下面的家具（工位桌、前台柜台、会议桌）例外：baseline 取**桌面前沿**，不取桌腿落地线。斜俯视的画里前排椅子推进了桌下，椅轮比桌腿落地线还靠北；桌子真正的深度是它正面那块，后排的人在它后面、前排的人在它前面，桌面前沿正好落在两排之间。桌子占地在可走栅格里不可走，走路的人不会落在桌面前沿和桌腿之间。中央竖隔板单独一件。`tools/occluders.mjs` 按多边形从 `background.png` 抠出带透明的图块，打包成 `occluders.png/json`，可复现。

**拆法。** 一个物体若一部分在坐着的人前面、一部分在后面，只抠在人前面的那部分：前排椅子（人背对观众）只抠椅背和扶手，坐垫留在背景里；后排椅子（人脸朝观众）整把都在人后面，不抠。

**排序。** 全场唯一的前后规则：`sortY` 大的画在上面。人的 `sortY` 是脚底，遮挡件的 `sortY` 是 `baseline`，`zIndexOf(sortY, bias)` 是唯一的换算函数。`bias` 只有一个约定：人 1、遮挡件 0（同一 y 上人在前）；排序测试要求座位和相关遮挡件的 y 严格不等，不依赖这个约定。不允许任何「zIndex = 某某 + 1」式的特例，不允许手调长方形遮挡。

**检查。**

- 单元测试：每个座位，坐下的人的脚底和它周围遮挡件的 `baseline` 满足前后关系（后排：人 < 桌；前排：人 < 椅背；前台：人 < 柜台；会议、沙发同理）。
- `tools/check-office.mjs`：所有座位坐满的全景和每个区域的放大图；外加一张「轮廓叠加图」——把每个多边形描成细线画在背景上、放大 3 倍，审图时看轮廓是否贴着物体边缘。
- 审图逐个看：脚和手落在哪、臀是否在坐垫上、肩是否在桌面上方、头是否在椅背前面、家具的朝向语义是否和人坐的位置一致。

## 4. 布局、座位与寻路

**布局文件** `apps/office/public/layout.json`（schema 在 `@idesk/shared/office-schemas`），数据目录 `IDESK_DATA_DIR/office/layout.json` 覆盖，不缓存。内容：背景尺寸、`occluders`、可走栅格、座位、工作区、命名点、`standing`、`meeting`、`lounge`、`hostZones`、`title`。

**座位**：`{ id, x, y, facing, mirror?, zone?, workSpot }`。`(x, y)` 是坐下时人的脚底，量法统一为「这把椅子落地点的中心」（椅轮或椅脚落在地板上的位置），不凭感觉调。落地点被桌子挡住的椅子（后排），用同款椅子换算：在一把完全可见的同款椅子上量一次「坐垫中心 → 落地点中心」的偏移，被挡的椅子一律取「可见的坐垫中心 + 同一偏移」，偏移写在 `assets/OCCLUDERS.md`，不逐把调。`facing` 取 `front`（后排，脸朝观众偏右下）、`back`（前排，背对观众偏右上）、`down`（前台礼仪，正对观众）、`left` / `right`（会议室两端、沙发侧坐）。每组工位右侧的座位 `mirror: true`，让人看向自己的显示器。`workSpot` 是桌面上放任务卡和台灯光的点。

**工作区**：每区若干座位和一个名牌文字区（背景木牌里的矩形，从画上量出）。分配规则不变：同一 `agent.host` 坐同一区，超出时循环，`hostZones` 可固定。工位不够时站到 `standing` 站位。

**寻路**：16px 一格的可走栅格（按行字符串，`.` 可走、`#` 不可走），格子 A* 加拐角平滑（第二版的 `path.ts`）。栅格由工具从遮挡件多边形生成初稿，再手工修正门口、过道、座位入口；座位所在格对要坐下的那个人可走。

## 5. 角色

- 每个智能体一个小人，外观由 `kind` 决定（claude-code 连帽衫、codex 衬衫眼镜、n8n 橙色马甲、script 鸭舌帽、custom 便装），不做运行时色相偏移（整张精灵转色相会把肤色染绿、把标志色改掉）；同类智能体靠名牌、名单和档案区分。
- 帧规格 64×96，脚底中点为锚点。素材全部取回第一版（提交 5a08051）的原图和切帧脚本，不量化颜色：走路图 4×5；工位用四分之三坐姿 `sit/front`、`typing/front/{0,1}`、`sit/back`、`typing/back/{0,1}`（front 朝右下、back 朝右上，`mirror` 座位水平镜像）；会议室两端和沙发侧坐用第 5 行侧坐帧；礼仪在前台用正面坐姿 `sit/down`、`typing/down/{0,1}`（第一版的 upright 三帧改名）。坐姿高度是站立帧的 0.85–0.90，头宽 ±10%。每帧的绘制锚点写在图集数据里（`characters.json` 帧的 `anchor`），含义统一为「这一帧的人落在地板上的点」：走路帧和脸朝前的坐姿帧，画面底边就是落地的脚，锚点 (0.5, 1)；背对观众的坐姿帧（`sit/back`、`typing/back/*`）腿藏在身前看不见，画面底边是臀和坐垫，精灵要上抬，抬升量以「肩膀露出椅背上沿 4–6px」为准（Q 版大头比例下，只按臀落坐垫量的 20px 会让椅背盖到下巴，只剩一颗头）；臀被椅背挡住，抬多少都看不见：Pixi 把贴图上的锚点放在落点上，所以 `anchor.y = (帧高 + 抬升) / 帧高` = 116/96（大于 1，Pixi 原样接受）；测试断言 back 帧精灵底边 = 座位 y − 20，防止写反。锚点表由 `tools/characters.mjs` 生成，量法写在 `assets/OCCLUDERS.md`；座位坐标和排序都不受影响，运行时没有任何坐姿特判。侧坐帧和礼仪正面坐姿的锚点在描完会议室、沙发、前台后按同样方法量。
- 状态机、空闲行为、打瞌睡、被指派与领取、礼仪、头顶气泡的规则沿用第一版（下文照录），「去处」是布局里的命名点，坐下的位置是布局里的座位。
- 状态机：`idle`（偶尔眨眼、换脚）、`walk`、`sit`、`typing`（有进行中任务）、`talk`（会议室，头顶省略号）、`coffee`（休息区）、`away`（离线，座位空着）。
- 空闲行为（第二版，要像人不像机器人）：布局里的命名点：打印机、书架、白板、窗边、绿植、沙发、咖啡机、会议室门口，每个是一个可走的格子、一个朝向和一句或几句气泡（字典 `idle.spot.*`，中英各一份，如「打印点东西」「看看窗外」「给花浇水」「翻翻书」）。没有进行中任务、不在会议室的角色，每 10–40 秒随机做一件事，概率不均等：小动作（伸懒腰气泡、左右张望、头轻点两下 = 精灵上下 1px 各 150ms）占一半；走一趟（随机挑一个 spot，走过去停 2–6 秒冒气泡再回座，偶尔连着去两个）占三成；找最近的空闲同事聊天（两人走到其中一人座位旁的过道格上面对面，轮流冒「…」「哈哈」「嗯嗯」各 1–2 秒，然后各回各位）占两成。走路速度每次在 120–170px/s 里随机，到站时精灵做一次 120ms 的压扁回弹。打瞌睡：3 分钟没有真实事件（空闲动作不算有事）就可能睡着，气泡「zZ」并每 4 秒慢慢点一下头；睡着的人不发起空闲动作也不被拉去聊天。睡 60–180 秒后自己醒来（伸懒腰气泡）重新开始空闲动作，真实事件立刻叫醒。同时睡着的人不超过空闲人数的三分之一，不能全员趴下，办公室要一直有人在动。被指派（task.assign）：头顶「!」0.8 秒，不走动，等接受后再去领卡；领取、接受、加入时：先冒「!」，再以 1.3 倍速小跑去任务板。同一时刻最多两人在走动，避免全员乱跑。`prefers-reduced-motion` 下只有气泡和头点，不走动。回放模式不跑。
- 前台礼仪：不接任务的 NPC，座位是前台柜台后那把正对观众的椅子。和智能体一样参与空闲行为（小动作、去各处、聊天、打瞌睡），做完回前台坐下；不随智能体上下线进出门。点击弹出礼仪档案：名字「礼仪」、岗位「前台礼仪」、爱好「爱吃小熊饼干」，不显示统计和指派。
- 头顶气泡：汇报进展时显示文字 4 秒；租约快到期显示「zzz」；完成时显示 ✓ 并撒一小把像素纸屑。

## 6. 事件到动作

Director 订阅 WebSocket，把事件翻译成角色意图；刷新页面时按当前 API 状态直接摆好位置，不回放历史。

| 事件 / 状态 | 动作 |
| --- | --- |
| 智能体 online | 从门走到自己的座位坐下 |
| 智能体 offline | 起身走出门，座位显示空椅 |
| task.created | 任务板上多一张卡，轻微弹跳 |
| task.claim / accept / join | 走到任务板，卡片飞到手里，走回座位，进入 typing |
| task.reported | 头顶气泡显示消息 |
| task.handoff | 走到接收者桌边把卡递过去（无接收者则钉回任务板），返回 |
| task.complete | ✓ 气泡 + 纸屑，卡片飞进已完成托盘，回到 idle |
| task.pause / resume | 走到休息区喝咖啡 / 走回座位 |
| task.release / lease_expired | 卡片飞回任务板 |
| 招募任务 joined 满员 | 团队成员走进会议室坐下，桌上出现任务卡；任务 done/cancel 后各回各位 |
| relay.sent | 一个信封从发送者飞到接收者桌上（广播飞到任务板旁的公告栏）；接收者短暂抬头 |
| 点击小人 | 页面正中弹出「同事档案」弹窗（见 §7），不再占用右列 |
| 点击任务板的卡 | 弹出任务详情（标题、能力、优先级），可一键打开主前端对应任务 |

回放：顶栏「回放」按钮进入回放模式，画布底部出现回放条（见 §7）。进入时停止处理 WS 事件（连接保留），用 `since=<ULID(now - 60 分钟)>` 循环拉取之后的全部事件（每次 200 条到空），按 `ts` 以所选速度喂给导演。没有历史快照，所以起点统一摆位：当前在线的智能体坐在座位 idle，任务板只放当前仍 open 的卡，之后由事件推进。「回到现场」重新拉 /agents 与 /events 按当前状态摆位（和刷新一样），恢复 WS 处理。

## 7. 界面外框

- 顶栏：场景名（可配置，默认「IDesk 调度中心」）、一句话状态（「3 人在线 · 2 个任务进行中」）、「回到看板」按钮。
- 工作区名牌：名牌是背景里现成的木牌，布局里写明它的文字区（从画上量出的矩形）。名字写在文字区里：像素字体、`#3B2A1A`，屏幕 12px 起逐级缩到 9px，仍放不下截断加「…」，悬停显示全名。
- 同事档案弹窗：点击小人（或名单项）在页面正中弹出，像素面板风格，宽 640，背后半透明墨色遮罩，Esc 或右上「×」关闭。内容从上到下：大头像（精灵正面帧放大 3 倍）+ 名字、kind、主机、能力、状态一句话；画像一行四个数字（完成 · 7 天完成 · 交接 · 平均耗时，`GET /agents/:id/stats`）；当前任务列表（标题 + 状态，点击打开主前端 `/desk?task=`）；最近事件 10 条（人话，同 §12.17）。底部动作区（只有管理员；只读访客不显示）：「指派任务」下拉列出待领取的任务，选中后点「指派」调 `POST /tasks/:id/actions/assign`；「发布并指派」展开标题 + 正文两个输入，提交 `POST /tasks` 带 `dispatch: { type: "assign", agentId }`；「发消息」展开标题 + 正文，提交 `POST /relay` 给该智能体，种类 note。动作成功后弹窗不关，列表刷新，顶部一行绿字提示 3 秒。右列仍是名单；点击任务卡仍用右列面板。
- 左右两列「今日值班」：按工作区分组列出智能体，每项是像素头像（精灵图正面第 1 帧裁头部）、名字、当前状态一句话；离线的灰显。超过 10 个时列内滚动。点击小人或任务卡打开的详情面板占用右侧这一列（同宽，替换名单），不盖住画布；关闭后名单回来。
- 面板风格：米白底、2px 深色像素描边、1px 内阴影，直角，像素字体（Fusion Pixel 12px，OFL，随包分发）。按钮同样描边，按下时整体下移 1px。
- 窄于 1100px 时两侧名单收成顶部一行头像。
- 顶栏右侧像素按钮：「EN / 中」语言切换（和主前端共用 `localStorage` 的 `idesk.lang`，规则见 DESIGN §12.18）、喇叭（声音开关，默认静音，存 `localStorage` 的 `office.sound`）、「回放」。
- 回放条：画布底部一条像素面板，内容从左到右：时间滑块（过去 60 分钟，刻度每 10 分钟）、播放/暂停、速度 1× / 10× / 60× 三选一、「回到现场」。拖滑块时跳到那一刻（从起点重新喂事件到该时刻，角色瞬移）。

## 8. 技术

- PixiJS 8 负责场景，React 只管外框和面板。不用 Phaser、GSAP、状态库、瓦片地图库。
- 补间用自己的 `tween(ticker, from, to, ms, ease)`；走路速度 140px/s（空闲时随机 120–170）。
- 数据：复用 `@idesk/shared` 的 schema 和主前端一样的 `request()`、WS 重连逻辑（复制一份，不跨 app import）。
- `prefers-reduced-motion`：角色瞬移到目标、无气泡动画；回放照样瞬移；不影响声音。
- 昼夜：按浏览器本地时间。20:00–06:00 夜间，背景和物体层整体叠 `#1a2340`（alpha 0.6，multiply）再叠同色 normal alpha 0.25；每个有人坐着的座位在它的 `workSpot` 画半径 40px 的暖光（`#ffd27a`，中心 alpha 0.5，add）。06:00–08:00 和 18:00–20:00 叠 `#ff9a3c` alpha 0.2。每分钟检查一次；编辑模式下关闭。
- 声音：WebAudio 合成，规则同第一版（领取、完成、交接、信封四种音，音量 0.1，默认静音，`office.sound`）。
- 传输：背景 WebP（质量 88）、角色图集与遮挡件图集 PNG，URL 带构建戳；`layout.json` 不缓存；像素字体按 unicode-range 分片按需加载。

## 9. 美术

- 背景沿用第一版那张插画，不重新生成，不做调色板量化。改布局就意味着重画整张图并重新描遮挡件，所以布局视为固定。
- 角色原图沿用第一版，不量化颜色，不做运行时色相偏移。
- 第二版的调色板、瓦片、家具图集、正面工位坐姿和对应工具全部删除。
- 素材生成方式（品红底、抠色、切帧、提示词入库）沿用第一版的 `tools/sprites.mjs` 和 `PROMPTS*.md`。

## 10. 编辑器

不做家具编辑器（背景是一整张画，家具不能挪）。按 `e` 进入的调试模式只做两件事：显示遮挡件轮廓、座位脚底点、可走栅格；可拖动座位点并导出 JSON，用来微调座位。

## 11. 不做的事

- 不做自由视角、缩放漫游；固定一屏，按窗口等比缩放。
- 不做多房间、多楼层；一间办公室，布局随背景固定。
- 不做每个智能体的自定义形象上传。
- 画布最多显示「座位数 + 站位数」个人；再多的人不画，也不列在名单里。
