# 像素办公室（/office）

一个可选的动效前端：把调度台画成一间像素风办公室，每个智能体是一个会走动的小人。它只是现有 API 和 WebSocket 事件的另一种视图，不改后端数据模型。现有的看板前端保留，`UI.md` 的 Apple 风格只管 `/desk` 等页面；`/office` 的视觉规范以本文为准。

参考气质：暖色像素办公室，斜俯视，Q 版两头身角色，左右两侧是像素描边的值班名单面板。

## 1. 部署形态

- 独立应用 `apps/office`（Vite + React 19 + PixiJS 8），构建产物由 API 在 `/office/` 托管，配置 `IDESK_OFFICE_DIST` 指向 dist；没配就不托管，主前端也不显示入口。
- 主前端侧栏在 `/office/` 可达时显示「像素办公室」入口（`GET /api/meta` 返回 `{ office: boolean }`）。
- Dockerfile 构建参数 `WITH_OFFICE`（默认 `true`）决定是否构建并打包 office；compose 里用 `build.args` 关掉即为「不部署」。
- office 自己不做登录页：未登录（401）时跳回主前端 `/login?from=/office/`。

## 2. 场景

一张生成的办公室背景图（2048×1152，像素风，斜俯视，暖色），上面叠加角色、任务卡、气泡等精灵。场景布局数据 `apps/office/src/scene/scene.json` 手工维护，包含：

| 区域 | 内容 | 对应 |
| --- | --- | --- |
| 前台 | 一张前台桌，后面坐着前台礼仪 | 发布者为 human 的任务从柜台上（`frontDesk.counter`）产生 |
| 任务板 | 墙上的白板，待领取的任务是钉在上面的卡片 | status=open / recruiting |
| 工作区 ×4 | 每区 4 张桌子，区名牌显示主机名 | 同一 `agent.host` 的智能体坐同一区；主机数超过 4 时按首次出现顺序循环分配；`scene.json` 里可用 `hostZones: { "mac-mini": 1 }` 固定 |
| 会议室 | 一张大桌 6 个座位 | 招募任务凑齐人后，团队成员坐到这里；任务结束各回各位 |
| 休息区 | 沙发、咖啡机 | 已暂停任务的负责人、长时间空闲的智能体；工位不够（在线超过 16 人）时，没座位的人站在休息区的站位上，站位满了沿过道排开，状态照常，名单里另列一组「站着的」 |
| 门 | 右下角 | 上线从门走进来，下线走出去 |
| 已完成托盘 | 前台旁的文件筐 | 完成的任务卡飞进去 |

寻路用手工标注的路点图（waypoints + edges，也在 scene.json 里）跑 A*，不做网格寻路。角色按 y 排序决定遮挡。按 `e` 进入编辑模式：可拖动座位、路点，右上角导出 JSON，方便改布局。

场景坐标直接用背景图的像素坐标（背景按生成的实际尺寸入库，不拉伸），整个舞台按窗口等比缩放。已部署的实例要改布局或 `hostZones` 时，不用重新构建：把编辑模式导出的 JSON 放到 `IDESK_DATA_DIR/office/scene.json`，API 在 `/office/scene.json` 优先返回它，没有就返回构建产物里的。

## 3. 角色

- 每个智能体一个小人，外观由 `kind` 决定基础套装（claude-code 连帽衫、codex 衬衫眼镜、n8n 橙色马甲、script 鸭舌帽、custom 便装），再按 id 哈希做色相偏移区分同类。
- 精灵图规格：每种角色两张图。原图 4 列 5 行：第 1–4 行是走路，行序 下/左/右/上，每行 4 帧循环（站、左脚、站、右脚）；第 5 行依次是侧坐（朝右）、打字帧 1、打字帧 2，第 4 格留空。补充图 `assets/raw/<kind>-seated.png` 4 列 2 行，参考原图只生成新增帧，单元格尺寸与原图一致：第 1 行 `sit/down`、`typing/down/0`、`typing/down/1`、`sit/up`，第 2 行 `typing/up/0`、`typing/up/1`、空、空。帧名按方向：`sit/{right,down,up}`、`typing/{right,down,up}/{0,1}`，left 用 right 镜像。25 帧一起求公共包围盒、底边对齐、水平居中，再最近邻等比缩放进 64×96。
- 状态机：`idle`（偶尔眨眼、换脚）、`walk`、`sit`、`typing`（有进行中任务）、`talk`（会议室，头顶省略号）、`coffee`（休息区）、`away`（离线，座位空着）。
- 坐姿朝向：背景里每组工位是前后两排——后排椅子在桌子后面、面朝下（看向屏幕、脸对观众），前排椅子在桌子前面、面朝上（背对观众）。现在 scene.json 把 16 个座位都放在桌子两侧、facing left/right，用侧坐帧，看起来是侧身坐在桌边、没对着桌子。改法：座位挪到椅子上，后排 `facing: down`，前排 `facing: up`；精灵图扩成 4×7，第六行 `sit-down`、`typing-down-1`、`typing-down-2`、`sit-up`，第七行 `typing-up-1`、`typing-up-2`、空、空，用 Codex 参考原图只生成新增的 4×2 补充图（原五行一个像素不动），`tools/sprites.mjs` 两张一起切；left / right 仍用第五行侧坐帧（会议室两侧的座位用得上）。坐姿帧的脚底对齐椅面：座位坐标就是椅面中心，角色锚点在脚底。
- 坐姿帧（第三版）：背景是斜俯视，显示器是斜着的，正对观众或正背对观众的坐姿和它对不上，而且压到七成高加整块遮挡只剩一个头，像漂着的脑袋。改成**四分之三视角**：补充图 4×2，第 1 行 `sit/front`（面朝观众偏右下，像在看斜放的显示器）、`typing/front/0`、`typing/front/1`、`sit/back`（背对观众偏右上）；第 2 行 `typing/back/0`、`typing/back/1`、空、空。front 帧朝右下、back 帧朝右上，每组右侧座位镜像（以显示器朝向为准，人要看向显示器）：座位加可选 `mirror: true`（scene.json 里写，编辑器不改），pose 在 front/back 时按它镜像，不填不镜像。高度是站立帧的 0.85–0.90（只收腿，不缩头和身子），头宽 ±10%。座位坐标仍是椅面中心、锚点在脚底。侧坐帧（第五行）只给会议室两侧和休息区用。
- 遮挡（第三版，实测后定）：座位的 `covers` 是若干背景切片，画在坐着的人之上、前排的人之下（zIndex = 座位 y + 1，不按切片底边）。后排座位两片：整块桌面（桌后沿 y≈262 到前沿 y≈360，本半边全宽）和显示器高出桌后沿的那一截；坐姿锚点放在桌后沿下方 13px（y=275）：大腿落在椅面上、小腿收进桌下，头、肩、胸和手臂整个露在桌面上方，人不显矮。前排座位一片：椅背。前台：柜台面（后沿 y≈640 往下 50px），座位标 `upright: true`，坐着时用正面站立帧（柜台挡住腿，看起来就是正对观众坐在柜台后），锚点 y=664。只盖桌沿一条是不够的：斜坐帧的腿伸向前方，会躺在桌面上。
- 空闲行为（第二版，要像人不像机器人）：`scene.json` 加 `spots`：打印机、书架、白板、窗边、绿植、沙发、咖啡机、会议室门口，每个带坐标、路点和一句或几句气泡（字典 `idle.spot.*`，中英各一份，如「打印点东西」「看看窗外」「给花浇水」「翻翻书」）。没有进行中任务、不在会议室的角色，每 10–40 秒随机做一件事，概率不均等：小动作（伸懒腰气泡、左右张望、头轻点两下 = 精灵上下 1px 各 150ms）占一半；走一趟（随机挑一个 spot，走过去停 2–6 秒冒气泡再回座，偶尔连着去两个）占三成；找最近的空闲同事聊天（两人各走到对方工位中点附近面对面，轮流冒「…」「哈哈」「嗯嗯」各 1–2 秒，然后各回各位）占两成。走路速度每次在 120–170px/s 里随机，到站时精灵做一次 120ms 的压扁回弹。打瞌睡：3 分钟没有真实事件（空闲动作不算有事）就可能睡着，气泡「zZ」并每 4 秒慢慢点一下头；睡着的人不发起空闲动作也不被拉去聊天。睡 60–180 秒后自己醒来（伸懒腰气泡）重新开始空闲动作，真实事件立刻叫醒。同时睡着的人不超过空闲人数的三分之一，不能全员趴下，办公室要一直有人在动。被指派（task.assign）：头顶「!」0.8 秒，不走动，等接受后再去领卡；领取、接受、加入时：先冒「!」，再以 1.3 倍速小跑去任务板。同一时刻最多两人在走动，避免全员乱跑。`prefers-reduced-motion` 下只有气泡和头点，不走动。回放模式不跑。
- 前台礼仪：不接任务的 NPC，座位是前台（`frontDesk.human`）。和智能体一样参与空闲行为（小动作、去各处、聊天、打瞌睡），做完回前台坐下；不随智能体上下线进出门。礼仪有专属角色图 `receptionist`（礼仪制服：深蓝西装外套、白衬衫、红色小丝巾，盘发；同画风同比例，4×5 走路图规格同其他角色），外加正对观众的坐姿补充图：`sit/upright`、`typing/upright/0`、`typing/upright/1`（身体正对观众、双手放在柜台面上、肩膀放松，不侧身；高度为站立帧的 0.85–0.90，头宽 ±10%）。前台座位带 `upright: true`，礼仪坐下时用这三帧，不再借站立帧。点击弹出礼仪档案：名字「礼仪」、岗位「前台礼仪」、爱好「爱吃小熊饼干」，不显示统计和指派。
- 头顶气泡：汇报进展时显示文字 4 秒；租约快到期显示「zzz」；完成时显示 ✓ 并撒一小把像素纸屑。

## 4. 事件到动作

Director 订阅 WebSocket，把事件翻译成角色意图；刷新页面时按当前 API 状态直接摆好位置，不回放历史。

| 事件 / 状态 | 动作 |
| --- | --- |
| 智能体 online | 从门走到自己的座位坐下 |
| 智能体 offline | 起身走出门，座位显示空椅 |
| task.created | 任务板上多一张卡，轻微弹跳 |
| task.claim / accept / join | 走到任务板，卡片飞到手里，走回座位，进入 typing |
| task.reported | 头顶气泡显示消息 |
| task.handoff | 走到接收者桌边把卡递过去（无接收者则钉回任务板），返回 |
| task.complete | ✓ 气泡 + 纸屑，卡片飞进已完成托盘，回到 idle |
| task.pause / resume | 走到休息区喝咖啡 / 走回座位 |
| task.release / lease_expired | 卡片飞回任务板 |
| 招募任务 joined 满员 | 团队成员走进会议室坐下，桌上出现任务卡；任务 done/cancel 后各回各位 |
| relay.sent | 一个信封从发送者飞到接收者桌上（广播飞到任务板旁的公告栏）；接收者短暂抬头 |
| 点击小人 | 页面正中弹出「同事档案」弹窗（见 §5），不再占用右列 |
| 点击任务板的卡 | 弹出任务详情（标题、能力、优先级），可一键打开主前端对应任务 |

回放：顶栏「回放」按钮进入回放模式，画布底部出现回放条（见 §5）。进入时停止处理 WS 事件（连接保留），用 `since=<ULID(now - 60 分钟)>` 循环拉取之后的全部事件（每次 200 条到空），按 `ts` 以所选速度喂给导演。没有历史快照，所以起点统一摆位：当前在线的智能体坐在座位 idle，任务板只放当前仍 open 的卡，之后由事件推进。「回到现场」重新拉 /agents 与 /events 按当前状态摆位（和刷新一样），恢复 WS 处理。

## 5. 界面外框

- 顶栏：场景名（可配置，默认「IDesk 调度中心」）、一句话状态（「3 人在线 · 2 个任务进行中」）、「回到看板」按钮。
- 工作区名牌：不画任何牌子。背景墙上每组工位已有一块空白木牌（`zone.name` 处，约 62×20 世界像素），名字直接写在它上面：像素字体、`#3B2A1A`，字号先按屏幕 12px 算，放不下就逐级缩到最小 9px，仍放不下就截断加「…」，鼠标悬停显示全名（Pixi 的 `eventMode` + 原生 title 用一个绝对定位的 div 代替）。文字垂直居中在牌面上，不能超出木框。
- 同事档案弹窗：点击小人（或名单项）在页面正中弹出，像素面板风格，宽 640，背后半透明墨色遮罩，Esc 或右上「×」关闭。内容从上到下：大头像（精灵正面帧放大 3 倍）+ 名字、kind、主机、能力、状态一句话；画像一行四个数字（完成 · 7 天完成 · 交接 · 平均耗时，`GET /agents/:id/stats`）；当前任务列表（标题 + 状态，点击打开主前端 `/desk?task=`）；最近事件 10 条（人话，同 §12.17）。底部动作区（只有管理员；只读访客不显示）：「指派任务」下拉列出待领取的任务，选中后点「指派」调 `POST /tasks/:id/actions/assign`；「发布并指派」展开标题 + 正文两个输入，提交 `POST /tasks` 带 `dispatch: { type: "assign", agentId }`；「发消息」展开标题 + 正文，提交 `POST /relay` 给该智能体，种类 note。动作成功后弹窗不关，列表刷新，顶部一行绿字提示 3 秒。右列仍是名单；点击任务卡仍用右列面板。
- 左右两列「今日值班」：按工作区分组列出智能体，每项是像素头像（精灵图正面第 1 帧裁头部）、名字、当前状态一句话；离线的灰显。超过 10 个时列内滚动。点击小人或任务卡打开的详情面板占用右侧这一列（同宽，替换名单），不盖住画布；关闭后名单回来。
- 面板风格：米白底、2px 深色像素描边、1px 内阴影，直角，像素字体（Fusion Pixel 12px，OFL，随包分发）。按钮同样描边，按下时整体下移 1px。
- 窄于 1100px 时两侧名单收成顶部一行头像。
- 顶栏右侧像素按钮：「EN / 中」语言切换（和主前端共用 `localStorage` 的 `idesk.lang`，规则见 DESIGN §12.18）、喇叭（声音开关，默认静音，存 `localStorage` 的 `office.sound`）、「回放」。
- 回放条：画布底部一条像素面板，内容从左到右：时间滑块（过去 60 分钟，刻度每 10 分钟）、播放/暂停、速度 1× / 10× / 60× 三选一、「回到现场」。拖滑块时跳到那一刻（从起点重新喂事件到该时刻，角色瞬移）。

## 6. 技术

- PixiJS 8 负责场景（精灵、容器、按 y 排序、ticker 驱动的补间），React 只管外框和面板。不用 Phaser、GSAP、状态库。
- 补间用自己的 20 行 `tween(ticker, from, to, ms, ease)`；走路速度固定 140px/s。
- 传输：背景图是 WebP（质量 88，约 190 KB），精灵图保持 PNG 无损；API 对 JS/JSON 开 gzip，带 hash 的构建产物缓存一年，背景、精灵图、字体缓存一天（换素材后一天内要强刷），`scene.json` 不缓存以便运行时覆盖。
- 数据：复用 `@idesk/shared` 的 schema 和主前端一样的 `request()`、WS 重连逻辑（复制一份，不跨 app import）。
- `prefers-reduced-motion`：角色瞬移到目标、无气泡动画；回放照样瞬移；不影响声音。
- 昼夜：按浏览器本地时间。20:00–06:00 夜间，整个背景叠一层 `#1a2340`、alpha 0.6、`multiply` 的色块，再叠一层同色 `normal`、alpha 0.25，让画面明显变暗变蓝；有人坐着的座位画一个半径 40px 的暖光径向渐变（`#ffd27a`，中心 alpha 0.5，`add` 混合，中心在角色脚底上方 10px 即桌面高度），夜间的色块和暖光都画在角色之上（世界顺序：背景 → 角色与座位遮挡 → 色块 → 暖光），人物和桌子一起被压暗、再被灯光照亮，夜里一眼能看出哪些工位亮着。06:00–08:00 和 18:00–20:00 叠 `#ff9a3c`、alpha 0.2。三种时段的截图并排看必须一眼分得出来。每分钟检查一次；编辑模式下关闭。不做天气：要位置和外部接口，办公室不调外部接口。
- 声音：WebAudio 合成，没有音频文件。领取 = 方波 440→660 Hz 各 60 ms；完成 = 523 / 659 / 784 Hz 各 80 ms；交接 = 660→440 Hz 各 60 ms；信封到达 = 880 Hz 40 ms。音量 0.1。响的时刻跟画面同步：领取在卡片到手时，完成在 ✓ 气泡出现时，交接在卡片起飞时，信封在到达时。AudioContext 在开关为开之后页面第一次 pointerdown 时创建（浏览器要求用户手势；刷新后开关仍为开，第一次点击之前的事件不出声）。
- 素材生成：由 Codex 的内置生图工具按 `apps/office/assets/PROMPTS.md` 里的提示词生成，背景一张，角色每种 kind 一张 4×5 原图加一张 4×2 坐姿补充图，统一品红 #FF00FF 底；脚本 `apps/office/tools/sprites.mjs` 做抠色（容差 60）、按连通区域的质心归入等分格来切帧（生图的像素不会严格对齐格线，头发可能越过一两格；连通区域整体归格就不会被切碎）、公共包围盒对齐、最近邻缩放到 64×96、打包成一张 TexturePacker hash 格式的图集 + JSON。提示词和生成结果都进仓库，重新生成可复现。

## 7. 不做的事

- 不做自由视角、缩放漫游；固定一屏，按窗口等比缩放。
- 不做多房间；一间办公室，4 个工作区。
- 不做每个智能体的自定义形象上传。
- 画布最多显示 35 人（16 个座位 + 3 个休息区站位 + 16 个过道站位）；再多的人不画，也不列在名单里。真要更多，改 scene.json 加站位。
