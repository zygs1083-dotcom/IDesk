# 像素办公室（/office）· 第二版

一个可选的动效前端：把调度台画成一间像素风办公室，每个智能体是一个会走动的小人。它只是现有 API 和 WebSocket 事件的另一种视图，不改后端数据模型。现有的看板前端保留，`UI.md` 的 Apple 风格只管 `/desk` 等页面；`/office` 的视觉规范以本文为准。

**为什么重做。** 第一版是「一张斜俯视的生成大图 + 手调长方形遮挡」。人和家具的前后关系只能靠肉眼一块块调，斜放的显示器又逼出四分之三坐姿，连续几版出现人嵌进柜台、腿躺在桌上、比椅子矮一截。第二版改用像素游戏的通用结构：正面俯视的格子地图，家具是独立精灵，人和家具统一按触地线排序。遮挡由结构保证，不再手调。第一版的场景、背景图、遮挡、路点、编辑器全部删除，不做兼容。

参考气质：暖色、安静的像素办公室，正面俯视（JRPG / Stardew Valley 那种视角），Q 版两头身角色，左右两侧是像素描边的值班名单面板。

## 1. 部署形态

- 独立应用 `apps/office`（Vite + React 19 + PixiJS 8），构建产物由 API 在 `/office/` 托管，配置 `IDESK_OFFICE_DIST` 指向 dist；没配就不托管，主前端也不显示入口。
- 主前端侧栏在 `/office/` 可达时显示「像素办公室」入口（`GET /api/meta` 返回 `{ office, build }`）。
- Dockerfile 构建参数 `WITH_OFFICE`（默认 `true`）决定是否构建并打包 office。
- office 自己不做登录页：未登录（401）时跳回主前端 `/login?from=/office/`。
- 部署后打开着的页面在 WS 重连时比对 `build`，变了就自动刷新；素材 URL 带构建戳。

## 2. 视角、格子与图层

**视角。** 正面俯视：地面是正对屏幕的矩形格子，桌椅都横平竖直，没有斜放的东西。人只有下、左、右、上四个朝向，坐姿也只有这四个。墙只画北墙（屏幕上方）和左右两侧的墙沿。

**格子。** 一格 32×32 世界像素，默认地图 40×24 格（1280×768）。一个世界像素就是一个美术像素，所有素材按这个密度出图，不在运行时缩放单个精灵。舞台按窗口等比缩放：比例 ≥ 1 时取整数倍，< 1 时按实际比例，始终最近邻采样。

**图层**（从下到上）：

1. 地面：地板、地毯，按格子铺。静态，启动时渲染成一张纹理。
2. 北墙：墙面、窗、挂钟、白板任务板、墙上名牌。人永远走不到墙里，所以墙整层在所有物体之下。
3. 物体层：家具的各个部件、人、桌上的任务卡，全部按 `sortY` 排序（见 §3），这是唯一需要排序的层。
4. 效果层：气泡、飞行中的卡片和信封、纸屑。永远在物体之上。
5. 光照：昼夜色块和工位暖光（§8）。

## 3. 家具与遮挡

**触地线排序。** 物体层里每个可见件都有一个 `sortY`：它和地面接触的那条线在世界坐标里的 y。人的 `sortY` 是脚底；家具的 `sortY` 是它占地矩形的下沿。`sortY` 大（离观众近）的画在上面，相等时按目录里的 `bias` 决定。这是全场唯一的前后规则，不允许任何「zIndex = 某某 + 1」式的特例。

**家具目录** `apps/office/public/catalog.json`，和家具图集 `furniture.png/json` 一起由工具生成。每件家具：

- `id`、`footprint`（占地，单位格，如桌子 `{w:3,h:2}`）、`blocks`（是否挡路）。
- `parts`：一个或多个部件，每个部件是图集里的一帧、相对占地左上角的绘制偏移、`sortY` 偏移和 `bias`。大多数家具只有一个部件；需要把人夹在中间的家具拆成 `behind` 和 `front` 两件，按「在坐着的人后面还是前面」拆，不按部件名拆：朝下的椅子 behind = 椅背 + 坐垫、front = 扶手；朝上的椅子 behind = 坐垫、front = 椅背 + 扶手；左右朝向同理。
- 椅子按朝向是四个条目（`chair-down/up/left/right`），各自带 `seat`：坐下时人的脚底点（相对占地）和朝向。朝下的椅子（人脸朝观众、坐在桌子北面）：椅背件 `sortY` 在人之前，人画在椅背上；桌子在人南面，桌子的 `sortY` 更大，自然盖住人的腿。朝上的椅子（人背对观众、坐在桌子南面）：椅背件 `sortY` 比人的脚底大一点，画在人的腰背上；桌子在北面，被人挡住。左右朝向同理，扶手件在靠观众一侧。
- 桌子按「人坐哪一侧」分两种：人朝上坐（背对观众）的桌子上放显示器，显示器靠桌面北沿、高出坐着的人的头顶；人朝下坐（脸朝观众）的桌子上放矮的笔记本电脑，不挡脸。桌子占地 3×2 格（桌面要有进深，否则南排背影会把显示器整个挡住）。桌子朝向观众的那一面按「人坐哪一侧」画：抽屉和腿洞永远朝着坐的人。人坐在南面（朝上坐）的桌子，南面画抽屉和腿洞；人坐在北面（朝下坐）的桌子，南面是一整块封闭的挡板，抽屉和腿洞在看不见的北面。朝下的椅子椅背比人的肩略宽、高到肩，从坐着的人两肩外侧露出一点，读得出「坐在椅子上」。朝上、朝下的椅子占地和桌子同宽（3×1），`seat.x` 在占地正中，布局坐标只用整数格；左右朝向的椅子 1×1，给会议桌两端用；侧向椅子和正向椅子同一比例（椅高约 44px、坐面到坐着的人的大腿），椅背在人身后（behind 件），左右两个朝向严格镜像对称。桌子带 `workSpot`：桌面上放任务卡和台灯光的点。
- 名牌 `plaque` 带 `textArea`；前台柜台、会议桌、沙发、书架、打印机、咖啡机、绿植、白板、文件筐、公告栏都是目录里的条目。

**为什么这样就对。** 人坐在柜台后面时，柜台的 `sortY`（它的落地前沿）一定比人的脚底大，于是整个柜台精灵——按它真实的轮廓——画在人上面，人只露出柜台上沿以上的部分。不存在「人嵌进台面」：没有任何手调的遮挡矩形可以调错。

**检查。** 单元测试遍历默认布局里的每个座位，断言坐下的人的 `sortY` 落在椅背件和桌子之间（朝下的椅子：椅背 < 人 < 桌；朝上的椅子：桌 < 人 < 椅背）。另有一个 Playwright 脚本 `tools/check-office.mjs`：所有座位坐满人渲染一张全景截图和每个工作区的放大图，提交到 `pr-assets`，审图时逐个看脚和手落在哪里。

## 4. 布局、座位与寻路

**布局文件** `apps/office/public/layout.json`（取代 scene.json）：地图尺寸、地面（按行的格子编码，如 `w` 木地板、`c` 地毯、`t` 瓷砖）、北墙装饰、物体列表（`{ item, x, y }`，单位格）、工作区（每区若干张桌椅的物体 id 和名牌 id）、命名点（门、任务板、文件筐、公告栏、前台柜台、各空闲去处）、`hostZones`。已部署的实例把布局放到 `IDESK_DATA_DIR/office/layout.json` 即覆盖构建里的版本，`/office/layout.json` 不缓存。

**默认布局**：北墙中间是白板任务板，左侧窗户；左下前台（柜台 + 朝下的椅子 + 服务铃 + 文件筐）；中间 4 个工作区，每区 2×2 张桌子面对面（北排人朝下、南排人朝上），区与区之间留两格过道；右上会议室（会议桌 6 座、玻璃隔断）；右下休息区（沙发、咖啡机、绿植）；门在南墙右侧。打印机、书架、绿植、窗边作为空闲去处。

**座位**：所有座位都来自椅子（和沙发的座位点），不在别处手写坐标。工作区座位的分配规则同第一版：同一 `agent.host` 的智能体坐同一区，主机数超过区数时循环分配，`hostZones` 可固定。工位不够时，没座位的人站在休息区和过道的站位上，名单里另列「站着的」。

**寻路**：格子 A*（四方向，拐角处走对角线平滑），可走格 = 地面格减去 `blocks` 家具的占地。座位所在的椅子格对要坐下的那个人可走。不再有手画的路点图。

## 5. 角色

- 每个智能体一个小人，外观由 `kind` 决定（claude-code 连帽衫、codex 衬衫眼镜、n8n 橙色马甲、script 鸭舌帽、custom 便装），同类按 id 做色相偏移（运行时的区分手段，调色板规则只约束素材文件）；前台礼仪 `receptionist` 不偏移。
- 帧规格 64×96，脚底中点为锚点。走路图沿用第一版的 4×5 原图（四方向各 4 帧，第 5 行侧坐与侧面打字）。坐姿重做为**正面四向**：`sit/{down,up}`、`typing/{down,up}/{0,1}`，侧面沿用第 5 行（left 由 right 镜像）。朝下坐：身体正对观众，双手在身前桌面高度；朝上坐：背对观众，手肘微张。高度是站立帧的 0.85–0.90，头宽 ±10%。第一版的四分之三坐姿帧删除。礼仪的 `sit/upright` 改名为 `sit/down`。
- 比例基准（探针第一版后定）：人站着约 3 格高、1.5 格宽，保持不变；家具按人放大：桌子 3 格宽，人的身宽约为桌宽一半；桌面高度到站着的人的腰；椅背到坐着的人的肩胛；南排背对观众坐着的人，头顶低于北沿显示器的上沿；前台柜台台面到站着的人的腰，坐着的礼仪露出头、肩、手。
- 状态机、空闲行为、打瞌睡、被指派与领取、礼仪、头顶气泡的规则沿用第一版（下文照录），只是「去处」换成布局里的命名点，坐下的位置换成椅子的 `seat`。
- 状态机：`idle`（偶尔眨眼、换脚）、`walk`、`sit`、`typing`（有进行中任务）、`talk`（会议室，头顶省略号）、`coffee`（休息区）、`away`（离线，座位空着）。
- 空闲行为（第二版，要像人不像机器人）：布局里的命名点：打印机、书架、白板、窗边、绿植、沙发、咖啡机、会议室门口，每个是一个可走的格子、一个朝向和一句或几句气泡（字典 `idle.spot.*`，中英各一份，如「打印点东西」「看看窗外」「给花浇水」「翻翻书」）。没有进行中任务、不在会议室的角色，每 10–40 秒随机做一件事，概率不均等：小动作（伸懒腰气泡、左右张望、头轻点两下 = 精灵上下 1px 各 150ms）占一半；走一趟（随机挑一个 spot，走过去停 2–6 秒冒气泡再回座，偶尔连着去两个）占三成；找最近的空闲同事聊天（两人走到其中一人座位旁的过道格上面对面，轮流冒「…」「哈哈」「嗯嗯」各 1–2 秒，然后各回各位）占两成。走路速度每次在 120–170px/s 里随机，到站时精灵做一次 120ms 的压扁回弹。打瞌睡：3 分钟没有真实事件（空闲动作不算有事）就可能睡着，气泡「zZ」并每 4 秒慢慢点一下头；睡着的人不发起空闲动作也不被拉去聊天。睡 60–180 秒后自己醒来（伸懒腰气泡）重新开始空闲动作，真实事件立刻叫醒。同时睡着的人不超过空闲人数的三分之一，不能全员趴下，办公室要一直有人在动。被指派（task.assign）：头顶「!」0.8 秒，不走动，等接受后再去领卡；领取、接受、加入时：先冒「!」，再以 1.3 倍速小跑去任务板。同一时刻最多两人在走动，避免全员乱跑。`prefers-reduced-motion` 下只有气泡和头点，不走动。回放模式不跑。
- 前台礼仪：不接任务的 NPC，座位是前台那把朝下的椅子。和智能体一样参与空闲行为（小动作、去各处、聊天、打瞌睡），做完回前台坐下；不随智能体上下线进出门。点击弹出礼仪档案：名字「礼仪」、岗位「前台礼仪」、爱好「爱吃小熊饼干」，不显示统计和指派。
- 头顶气泡：汇报进展时显示文字 4 秒；租约快到期显示「zzz」；完成时显示 ✓ 并撒一小把像素纸屑。

## 6. 事件到动作

Director 订阅 WebSocket，把事件翻译成角色意图；刷新页面时按当前 API 状态直接摆好位置，不回放历史。

| 事件 / 状态 | 动作 |
| --- | --- |
| 智能体 online | 从门走到自己的座位坐下 |
| 智能体 offline | 起身走出门，座位显示空椅 |
| task.created | 任务板上多一张卡，轻微弹跳 |
| task.claim / accept / join | 走到任务板，卡片飞到手里，走回座位，进入 typing |
| task.reported | 头顶气泡显示消息 |
| task.handoff | 走到接收者桌边把卡递过去（无接收者则钉回任务板），返回 |
| task.complete | ✓ 气泡 + 纸屑，卡片飞进已完成托盘，回到 idle |
| task.pause / resume | 走到休息区喝咖啡 / 走回座位 |
| task.release / lease_expired | 卡片飞回任务板 |
| 招募任务 joined 满员 | 团队成员走进会议室坐下，桌上出现任务卡；任务 done/cancel 后各回各位 |
| relay.sent | 一个信封从发送者飞到接收者桌上（广播飞到任务板旁的公告栏）；接收者短暂抬头 |
| 点击小人 | 页面正中弹出「同事档案」弹窗（见 §7），不再占用右列 |
| 点击任务板的卡 | 弹出任务详情（标题、能力、优先级），可一键打开主前端对应任务 |

回放：顶栏「回放」按钮进入回放模式，画布底部出现回放条（见 §7）。进入时停止处理 WS 事件（连接保留），用 `since=<ULID(now - 60 分钟)>` 循环拉取之后的全部事件（每次 200 条到空），按 `ts` 以所选速度喂给导演。没有历史快照，所以起点统一摆位：当前在线的智能体坐在座位 idle，任务板只放当前仍 open 的卡，之后由事件推进。「回到现场」重新拉 /agents 与 /events 按当前状态摆位（和刷新一样），恢复 WS 处理。

## 7. 界面外框

- 顶栏：场景名（可配置，默认「IDesk 调度中心」）、一句话状态（「3 人在线 · 2 个任务进行中」）、「回到看板」按钮。
- 工作区名牌：墙上的名牌是一件家具（`plaque`），目录里写明它的文字区（相对精灵的矩形，从精灵本身量出）。名字写在文字区里：像素字体、`#3B2A1A`，屏幕 12px 起逐级缩到 9px，仍放不下截断加「…」，悬停显示全名。
- 同事档案弹窗：点击小人（或名单项）在页面正中弹出，像素面板风格，宽 640，背后半透明墨色遮罩，Esc 或右上「×」关闭。内容从上到下：大头像（精灵正面帧放大 3 倍）+ 名字、kind、主机、能力、状态一句话；画像一行四个数字（完成 · 7 天完成 · 交接 · 平均耗时，`GET /agents/:id/stats`）；当前任务列表（标题 + 状态，点击打开主前端 `/desk?task=`）；最近事件 10 条（人话，同 §12.17）。底部动作区（只有管理员；只读访客不显示）：「指派任务」下拉列出待领取的任务，选中后点「指派」调 `POST /tasks/:id/actions/assign`；「发布并指派」展开标题 + 正文两个输入，提交 `POST /tasks` 带 `dispatch: { type: "assign", agentId }`；「发消息」展开标题 + 正文，提交 `POST /relay` 给该智能体，种类 note。动作成功后弹窗不关，列表刷新，顶部一行绿字提示 3 秒。右列仍是名单；点击任务卡仍用右列面板。
- 左右两列「今日值班」：按工作区分组列出智能体，每项是像素头像（精灵图正面第 1 帧裁头部）、名字、当前状态一句话；离线的灰显。超过 10 个时列内滚动。点击小人或任务卡打开的详情面板占用右侧这一列（同宽，替换名单），不盖住画布；关闭后名单回来。
- 面板风格：米白底、2px 深色像素描边、1px 内阴影，直角，像素字体（Fusion Pixel 12px，OFL，随包分发）。按钮同样描边，按下时整体下移 1px。
- 窄于 1100px 时两侧名单收成顶部一行头像。
- 顶栏右侧像素按钮：「EN / 中」语言切换（和主前端共用 `localStorage` 的 `idesk.lang`，规则见 DESIGN §12.18）、喇叭（声音开关，默认静音，存 `localStorage` 的 `office.sound`）、「回放」。
- 回放条：画布底部一条像素面板，内容从左到右：时间滑块（过去 60 分钟，刻度每 10 分钟）、播放/暂停、速度 1× / 10× / 60× 三选一、「回到现场」。拖滑块时跳到那一刻（从起点重新喂事件到该时刻，角色瞬移）。

## 8. 技术

- PixiJS 8 负责场景，React 只管外框和面板。不用 Phaser、GSAP、状态库、瓦片地图库。
- 补间用自己的 `tween(ticker, from, to, ms, ease)`；走路速度 140px/s（空闲时随机 120–170）。
- 数据：复用 `@idesk/shared` 的 schema 和主前端一样的 `request()`、WS 重连逻辑（复制一份，不跨 app import）。
- `prefers-reduced-motion`：角色瞬移到目标、无气泡动画；回放照样瞬移；不影响声音。
- 昼夜：按浏览器本地时间。20:00–06:00 夜间，地面、墙和物体层整体叠 `#1a2340`（alpha 0.6，multiply）再叠同色 normal alpha 0.25；每张有人坐着的桌子在 `workSpot` 画半径 40px 的暖光（`#ffd27a`，中心 alpha 0.5，add）。06:00–08:00 和 18:00–20:00 叠 `#ff9a3c` alpha 0.2。每分钟检查一次；编辑模式下关闭。
- 声音：WebAudio 合成，规则同第一版（领取、完成、交接、信封四种音，音量 0.1，默认静音，`office.sound`）。
- 传输：家具图集、角色图集、地面纹理都是 PNG 无损，URL 带构建戳；`layout.json`、`catalog.json` 不缓存。

## 9. 美术

**风格约束**（去 AI 味的硬规则）：

- 全场共用一套调色板（`assets/palette.png`，不超过 40 色）：基础 32 色；`tools/palette.mjs` 再保证每种角色的标志色在调色板里（每种 kind 原图里面积最大的两种有彩色衣物或配饰的颜色，取色域的面积加权中心；HSV 饱和度 < 0.15 的灰黑白不算标志色，交给 k-means；量化后 RGB 距离 ≤ 20，否则把该色追加到调色板末尾，已有颜色的顺序和取值不动），剩余名额用整套角色像素 k-means 取量化残差最大的簇补齐，可复现；用途见 `assets/PALETTE.md`。礼仪的红丝巾、claude-code 的青色连帽衫这类标志色量化后不能变成别的颜色，所有素材出图后量化到它；不允许渐变、噪点、模糊、半透明边。地毯用浅米色或暖灰褐，不用墨绿这类和木地板对比强烈的颜色。
- 1px 深色描边（不是纯黑，用调色板里最深的暖棕），光从左上来，每件家具最多三级明暗。
- 素材里不画任何文字；名牌、白板上的字都由程序写。
- 一个世界像素 = 一个美术像素，同屏素材像素密度一致。

**生产方式**：Codex 内置生图工具出原图（品红 `#FF00FF` 底），`tools/sprites.mjs`（角色）和 `tools/furniture.mjs`（家具）抠色、按清单切帧、量化到调色板、最近邻缩放到目录里写明的尺寸、打包图集。地板、墙面这类要无缝平铺的格子用 `tools/tiles.mjs` 按调色板程序化画（木纹条、地毯织纹、墙裙），不用生图，保证无接缝。提示词、原图、清单都进仓库，重新生成可复现。

**探针先行**：正式出全套素材之前，先做一个探针：一个工作区（4 桌 4 椅，两种朝向）、前台（柜台 + 椅子）、一盆绿植、一个书架、地板和北墙一段、一个角色的四向坐姿，在新引擎里摆出来截图。负责人把截图给用户确认风格后，才批量出图。

## 10. 编辑器

管理员按 `e` 进入编辑模式：左侧是家具目录，点选后在地图上点击放置，拖动移动，`R` 换朝向（椅子、桌子），`Delete` 删除，地面可按格子刷三种材质；工作区在编辑器里框选桌椅生成。右上「导出 JSON」下载 `layout.json`，「保存」调 `PUT /api/v1/office/layout`（仅管理员，写到 `IDESK_DATA_DIR/office/layout.json`，保存前用和前端同一个 schema 校验）。保存后其他打开着的页面在下次刷新时生效，不做实时同步。

## 11. 不做的事

- 不做自由视角、缩放漫游；固定一屏，按窗口等比缩放。
- 不做多房间、多楼层；一间办公室。
- 不做每个智能体的自定义形象上传。
- 不做斜放的家具和八方向角色。
- 画布最多显示「座位数 + 站位数」个人；再多的人不画，也不列在名单里。
